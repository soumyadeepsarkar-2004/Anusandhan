## 4. Specific Recommendations for 1,000-User Production Readiness

To transition the verified codebase into long-term cloud production serving 1,000+ active scholars, the following finalizations are recommended:

1. **Database Schema & Persistence Alignment**:
   - In `server/models/Student.js`, add `id: { type: String, unique: true, index: true }` to `StudentSchema` so that `Student.findOne({ id: studentId })` and `Student.findOneAndUpdate({ id: studentId })` map cleanly to indexed MongoDB documents when MongoDB is connected.
   - In `server/routes/outreachRoutes.js:117-122`, add `await Outreach.findOneAndUpdate({ _id: id, studentId }, { status })` alongside the in-memory fallback to ensure CRM stage updates persist to the database.

2. **Secrets & Environment Externalization**:
   - In `docker-compose.prod.yml`, ensure `JWT_SECRET` is supplied via production `.env` rather than relying on default compose strings.
   - For Kubernetes deployments, ensure `k8s/02-secrets.yaml` values are sealed via HashiCorp Vault or Kubernetes Sealed Secrets.

3. **External API Circuit Breaking & Rate Limits**:
   - In `server/services/dataIngestionService.js`, the arXiv API rate limit of 1 request per 3 seconds should be guarded with a leaky-bucket rate limiter or Redis distributed lock if multiple gateway replicas run in parallel.
   - Configure a fallback circuit breaker for Gemini 3.8 Flash calls so high-volume viva requests degrade gracefully to heuristic responses without stalling the FastAPI worker pool.

4. **Production Deployment Execution**:
   - Launch with `docker compose -f docker-compose.prod.yml up -d` or deploy via `kubectl apply -f k8s/` in the `anusandhan-production` namespace.
   - Run `node scripts/validate_environment.js` as an init container or CI/CD deployment gate.
